STEM創課-解密四軸無人機

教師教學規畫、模組設計脈絡與教學策略。學生實際操作請由 index.html 進入各任務頁。
智高 #1413STEAM 任務探究系統思考演算法與控制工程設計

課程定位

本課程不是「學會操控無人機」的飛行課，而是以四軸無人機作為系統載具，帶學生逐步理解結構、動力、協同、感測、回授控制、演算法與工程創新。

桌面探究為主實體觀察、結構組裝、機電實作、量測與工程改造。
模擬輔助理解只在實體現象不易看見或需要放大概念時使用。
低飛行依賴真實飛行只作必要展示或驗證，不作課程主軸。
整體學習進程：
看懂系統 → 做出結構 → 理解動力 → 理解四軸協同 → 理解感測 → 理解控制 → 轉成演算法 → 工程創新

共用任務設計原則

每一個模組都從核心提問出發，不強迫套用固定教學流程。設計時先問：「為了讓學生真正回答這個問題，需要哪些活動與證據？」

必要核心：
① 一個值得探究的問題 → ② 足以回答問題的活動與證據 → ③ 形成概念、模型或下一個問題。
必要 核心提問
決定本關真正要破解什麼。
情境／引起動機
需要建立問題意識時使用。
體驗／觀察
需要形成直接經驗時使用。

需要揭露學生原有概念時使用。
探究／實作／量測
需要操作變因或取得證據時使用。
模擬／可視化
用於實體中不易直接看見的機制。
統整

反思／工程改造
檢查證據、限制，或依問題修正設計。
鷹架策略：任務先行、鷹架伴隨。知識鷹架只在學生遇到認知瓶頸時提供，不作所有學生必讀的前置教材。

M0～M7 教學規畫

M0
系統解密
一架四軸無人機裡藏了什麼？
從完整機體出發，透過猜想、功能配對與子系統分類，建立「結構、能源、動力、感測、控制、通訊、程式」的整體科技系統觀，再以輸入、處理、輸出、回授整理運作脈絡。
學生任務頁教學設計文件
M1
機體結構
怎樣的「身體」比較穩？
以智高四軸機體作為工程檢核對象，聚焦幾何對稱、結構剛性、輕量化、防護與安全、線路收納。學生觀察、檢核、診斷並修正機體結構品質，而非以控制變因實驗為主。
學生任務頁教學設計文件
M2
動力解密
螺旋槳如何把電變成推力？
由單馬達與螺旋槳體驗進入推力量測，形成「電能 → 馬達旋轉 → 螺旋槳推動空氣 → 推力」的概念鏈，再用模擬放大不可見機制。
學生任務頁
M3
四軸協同
四顆馬達要怎麼一起工作？
由上升、下降、前後左右與旋轉等動作需求，逆向觀察四顆馬達輸出如何協同改變，建立差動推力、正反轉與姿態改變的關係。
學生任務頁教學設計文件
M4
感知世界
無人機怎麼知道自己飛多高、移動了多少？
從「機器需要知道什麼」反推感測方式，理解 ToF 距離資料與 Optical Flow 相對移動線索，以及環境條件對感測品質的影響。
學生任務頁教學設計文件
M5
智慧控制
機器怎麼自己修正？
以目標值、感測值、誤差與修正建立閉迴路概念，讓學生理解「目標值 → 感測值 → 比較 → 誤差 → 修正 → 再感測」。
學生任務頁教學設計文件
M6
程式與任務
如何讓無人機依照規則自己完成任務？
由操作進入演算法，以任務拆解、順序、參數、迴圈、條件與除錯，讓學生把前面學過的感測與控制轉成可執行流程。
學生任務頁教學設計文件
M7
工程創新
同一套零件，可以變成什麼？
以工程任務整合 M1～M6 的概念，從需求、限制、系統模組、原型測試到改造，用「我改了什麼 → 造成什麼結果 → 我怎麼知道 → 下一次怎麼改」呈現工程學習歷程。
學生任務頁教學設計文件

教師實施提醒

面向建議
安全優先使用桌面探究與固定式測試；真實飛行僅在必要時短時間展示。槳葉周圍需保持安全距離。
概念順序避免提前把後續模組的答案講完。例如 M4 只處理感測，不先深入 M5 回授控制。
學生紀錄只保留真正有學習價值的證據，不把每一步操作都變成文字作答。
模擬器定位為概念模型，不把模擬數值誤當成 #1413 實際量測校正值。
評量優先看學生是否能用現象、數據或作品說明「我改了什麼、造成什麼結果、我怎麼知道」。
