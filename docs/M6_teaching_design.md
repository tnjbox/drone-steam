# M6｜程式與任務：如何讓無人機依照規則自己完成任務？

## 一、模組定位
M6 承接 M5：學生已知道機器可以利用感測資料與目標值持續修正自己。現在進一步處理：如果任務不是「維持某個狀態」，而是「完成一連串任務」，機器要怎麼把任務轉成一組可執行、可驗證、可修正的規則？

核心認知路徑：

> **任務 → 拆解動作 → 排序 → 設定參數 → 執行 → 驗證 → 發現重複 → 加入條件 → 修正演算法**

本模組不先教程式語法，而是先讓學生透過模擬任務產生對「循序、迴圈、條件判斷、演算法」的實際需求。

---
## 二、核心問題
**如何讓無人機依照規則自己完成任務？**

子問題：
1. 給定起點與目標，如何規劃飛行流程？
2. 指令的先後順序與參數如何影響結果？
3. 理論流程正確，為什麼實際執行仍可能偏離？
4. 哪些重複規則適合用迴圈表示？
5. 當環境與狀態會改變時，固定流程夠不夠？
6. 人是怎麼做即時判斷的？這個判斷規則能不能交給程式？

---
## 三、核心概念
1. **Sequence｜循序**：依照指定先後順序執行。
2. **Parameter｜參數**：距離、角度、時間等會改變指令效果。
3. **Loop｜迴圈**：相同規則重複多次時，用重複結構描述。
4. **Condition｜條件判斷**：根據目前資料決定下一步。
5. **Algorithm｜演算法**：為完成任務而設計的一組清楚、有限、可執行且可驗證的步驟。
6. **Debugging｜除錯與修正**：比較預期與結果，再修改流程或參數。
7. **Simulation｜模擬驗證**：先在模型中檢查演算法，再討論真實世界的不確定性。

---
## 四、M6 模擬器的三個主任務

### A｜循序任務：先把任務拆成步驟
- 起點固定在地圖中央。
- 初始機頭朝上。
- 目標在可視格線範圍內隨機產生。
- 地圖固定 **1 格＝50 cm**。

學生自行加入起飛、前進、後退、左移、右移、左轉、右轉、等待、降落等指令，並設定距離與角度。

#### 理論版
沒有風與隨機偏差，用來檢查：
> **流程、順序、參數本身是否正確？**

#### 實際版
加入示意性的方向、距離與風擾誤差，用來比較：
> **同一套流程，為什麼實際結果可能和理論結果不同？**

本活動建立：
> 任務規劃 → 循序 → 參數 → 執行 → 驗證

---
## 五、B｜迴圈任務：從重複規則產生迴圈需求
模擬器隨機產生 3～6 邊的正多邊形巡檢任務。

設計條件：
- 多邊形總周長固定為 **1350 cm**。
- 每邊距離 = 1350 ÷ 邊數。
- 起點在格線交叉點。
- 學生必須自行觀察、推算並輸入：
  1. 每邊距離
  2. 每次轉角
  3. 重複次數
- 系統不自動載入答案。

學生先看到展開版，再比較迴圈版：

> 前進 → 轉向 → 前進 → 轉向……

轉成：

> 重複 N 次：前進某距離 → 轉向某角度

此活動不是先教「迴圈語法」，而是讓學生先發現重複模式，再產生壓縮規則的需求。

## 六、C｜條件修正：先由人判斷，再把規則交給程式
C 任務分為兩個子模式，兩者使用相同任務概念。

### C1｜我來當控制器
學生每一次都自行讀取目前狀態，再設定：
- 相對修正角度 Δθ：**-30°～+30°**
  - 負值＝逆時針／左轉
  - 0°＝維持方向
  - 正值＝順時針／右轉
- 前進距離：**10～50 cm**

每按一次，只執行一次學生當下的決定：

> 看狀態 → 決定 Δθ → 調整目前機頭方向 → 前進 → 再觀察

學生本人就是控制器。

### C2｜讓程式當控制器
學生設定：
- 每次轉向幅度：**5～30°**
- 每次前進距離：**10～50 cm**

程式根據感測結果決定左轉、右轉或維持方向。

每按一次，只慢動作執行一輪：

> 感測 → 判斷 → 修正 → 前進 → 停下來

再按一次才會進行下一輪。

此設計刻意讓學生先親自做判斷，再思考：

> **我剛才反覆做的判斷，能不能整理成規則交給程式？**

這就是從「人工決策」進入「條件判斷程式化」的認知轉折。

---
## 七、C 任務中的誤差與失敗
條件修正任務保留教學示意性的感測與飛行誤差，使學生看到：
- 感測資料不是絕對真值。
- 一次修正不一定到位。
- 可能修過頭、震盪或偏離。
- 不適當參數可能導致失敗。

模擬器不替學生偷偷修正輸入參數。

任務可能因：
- 飛出地圖範圍；
- 在限定修正次數內仍未到達；
而判定失敗。

因此學生可以真正進行：

> **參數設計 → 執行 → 觀察 → 失敗／震盪 → 修改 → 再測試**

---
## 八、M4、M5、M6 的整合關係
M4：
> **我現在在哪裡／目前狀態是什麼？**

M5：
> **和目標差多少？該往哪裡修正？**

M6：
> **如何把任務、重複與判斷整理成程式可以執行的規則？**

因此 M6 的條件任務不是重新教一次回授，而是把前面的感測與修正概念放進「任務層級的演算法」中。

## 九、學生學習證據
M6 數位紀錄只保留必要證據：

1. **A｜循序任務過關紀錄**
2. **理論版與實際版的差異**

4. **學生找到的重複規則**
5. **C｜條件修正過關紀錄**

不要求學生記錄每一次無效試誤。

## 十、可選式鷹架
M6 採「任務先行、鷹架伴隨」。鷹架不預設展開，只在實際認知卡點提供。

### 1. `scaffolds/m6-algorithm.html`｜什麼是演算法？
掛載位置：A 循序任務後與統整階段。

協助學生理解：
- 任務不等於演算法。
- 演算法需要清楚、有序、可執行、會結束。
- 程式能跑不代表任務一定成功，還需要驗證。

### 2. `scaffolds/m6-sequence-loop.html`｜循序與迴圈
掛載位置：B 多邊形巡檢。

協助學生比較：
- 展開版與迴圈版如何描述同一條路徑。
- 哪一段規則重複？
- 重複幾次？
- 哪些參數固定？

### 3. `scaffolds/m6-condition.html`｜條件判斷
掛載位置：C1 / C2 比較。

協助學生理解：
- C1 是「人當控制器」。
- C2 是「把判斷規則交給程式」。
- 條件判斷是根據目前狀態決定下一步，不是固定執行同一指令。

---
## 十一、模擬器邊界
- 隨機誤差是教學示意，不是 #1413 實測分布。
- 不宣稱風、PWM、距離、角度之間具有此模擬器所示的精密數學關係。
- 地圖與距離比例是課程模型。
- C 任務中的感測方向與誤差是為了呈現「狀態會改變、資料有不確定性」的概念。
- M6 的重點是任務層級演算法，不是建立真實飛控系統。
