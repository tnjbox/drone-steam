# M0｜系統解密：一架四軸無人機裡藏了什麼？

## 一、模組定位

M0 是「STEM創課-解密四軸無人機」的序章任務，目的不是先教完整飛行原理，也不是要求學生背零件名稱，而是建立一張能支撐 M1～M7 的科技系統地圖。

核心轉變：

> 從「看到一架無人機」→「看見多個子系統正在合作」

M0 完成後，學生應知道：一架四軸無人機不是四顆馬達加上一個機架，而是一個由結構、能源、動力、感測、控制、通訊與程式等功能共同組成的科技系統。

七類子系統是本課程的分析工具，不代表所有科技產品都必須具有完全相同的七個子系統。

---

## 二、核心提問

**一架四軸無人機裡藏了什麼？**

延伸追問：

> 這些不同部分各自負責什麼？又如何合作成一個能完成任務的科技系統？

---

## 三、核心概念鏈

> **完整機體 → 猜想零件 → 配對功能 → 分類子系統 → 科技系統運作模型**

M0 不要求學生一次背熟名詞，而是先從功能判斷，最後才形成子系統分類與整體科技系統觀。

---

## 四、子系統分類

### 結構 Structure
支撐、固定、保護與安排其他元件的位置。例如機架、機臂、馬達固定結構、螺旋槳護罩。

### 能源 Energy
提供系統運作所需的電能，例如 3.7V 鋰電池與電源連接。

### 動力 Power / Actuation
把電能轉換成可以造成動作的輸出，例如馬達與螺旋槳。

### 感測 Sensing
取得外界或自身狀態資料，例如 ToF 距離感測與 Optical Flow 光流移動線索。

### 控制 Control
根據操作命令、目標與感測資料，判斷並協調輸出。控制是一種功能與過程，不只是某一顆硬體。

### 通訊 Communication
讓操作者、遙控器或其他裝置把命令傳給系統，例如 2.4G 遙控器與控制板之間的命令傳遞。

### 程式 Program / Algorithm
把任務規則、操作順序與判斷條件轉成機器可執行的流程。M0 只建立「程式也是系統的一部分」的概念，不提前進入 M6 演算法細節。

---

## 五、教學設計原則

### 原則 1｜功能先於名詞
先看實體或圖片，問「它負責做什麼？」再逐步形成分類。

### 原則 2｜零件不等於子系統
同一個子系統可能包含多個元件；一個元件也可能同時參與多個功能。

### 原則 3｜學生先做可負擔的判斷，教師再完成概念統整
M0 的學生任務以勾選、配對與分類為主。對缺乏科技系統背景的學生，不要求自行建構完整的「輸入—處理—輸出—回授」模型，而是在學生完成前三項任務後，由平台直接呈現並由教師統整。

### 原則 4｜M0 不深入後續原理
M0 只建立系統觀，不在此處詳細解釋：重心與穩定（M1）、推力（M2）、四馬達協同（M3）、ToF／光流原理（M4）、回授控制（M5）、演算法（M6）。

## 六、學習活動

### 01｜猜想：拆開後可能有什麼？

用去背四軸無人機作為任務主圖。學生不從空白頁開始寫，而是從預設選項中多選猜想，包含主要元件與少量干擾項，以降低書寫負擔並保留原始概念。

建議主要選項：機架／機臂、護罩、電池、馬達、螺旋槳、主控盒／控制板、感測器、電線／連接線、通訊／遙控接收、程式。

干擾項可包含：輪胎、水箱、喇叭、太陽能板。

只保留一個簡短補充：學生最想先研究哪一部分，以及原因。

---

### 02｜配對：零件主要負責什麼？

讓學生觀察實體元件或教師展示，再使用下拉選單完成「元件 → 主要功能」配對。

目標不是一次全對，而是把注意力從零件名稱轉向功能。

建議配對包含：
- 機架／機臂／護罩 → 支撐、固定與保護
- 電池 → 提供電力
- 馬達＋螺旋槳 → 產生旋轉動力與推力
- ToF／光流感測 → 取得距離／移動資料
- 主控盒／控制板 → 判斷並協調各部分輸出
- 遙控器／2.4G 通訊 → 接收或傳送命令
- 程式 → 依規則組織與執行任務

---

### 03｜分類：把零件放進主要所屬子系統

此時才引入：

> 結構｜能源｜動力｜感測｜控制｜通訊｜程式

平台採雙模式操作：
- 桌機：拖曳卡片到分類區。
- 平板／手機：先點卡片，再點分類區。

分類不是背答案，而是把功能相近的元件整理在一起。平台不在此階段強制自動判分，保留教師討論與學生修正空間。

---

### 04｜統整：直接帶入科技系統「輸入—處理—輸出—回授」

學生完成分類後，平台直接呈現四軸無人機的簡化科技系統模型，不要求學生先自行作答。

#### 輸入 Input
- 操作者／程式的任務命令
- 遙控通訊資料
- 電池提供的電能
- 感測器取得的狀態資料

#### 處理 Process
主控盒／控制板執行程式，解讀命令與感測資料，決定四顆馬達應該如何輸出。

#### 輸出 Output
馬達帶動螺旋槳產生推力，使機體上升、下降、移動或旋轉。

#### 回授／回饋 Feedback
ToF、光流等感測器再次取得現在的高度或移動狀態，把資料送回控制端，讓系統知道實際結果。

簡化回授鏈：

> **實際狀態 → 感測資料 → 回到控制端 → 必要時再調整輸出**

此處只建立整體輪廓，不深入 M5 的誤差與閉迴路控制。

### 兩種系統觀點要明確區分

- 「結構、能源、動力、感測、控制、通訊、程式」＝看系統**有哪些功能**。
- 「輸入、處理、輸出、回授」＝看這些功能**如何連成運作流程**。

## 七、M1 預告

M0 結束只做預告，不要求學生在此先回答 M1。

呈現：

> **M1｜機體結構：怎樣的「身體」比較穩？**

說明下一關將從結構子系統出發，探究形狀、對稱、重心與重量分布如何影響機體穩定。

不再設置：
- 「我對 M1 的預測」
- 「我最想繼續研究的新問題」

## 八、學生數位紀錄

M0 是序章，不需要大量書寫。只保留：

1. 01 原始猜想勾選結果與一個感興趣的部分。
2. 02 零件與功能配對結果。
3. 03 子系統分類結果。
4. 04 科技系統統整由平台直接呈現，也可一併納入 PDF 作為學習成果脈絡，但不要求額外作答。

## 九、完成標準

學生完成 M0 後，至少能：

1. 從選項中辨識多個無人機可能包含的元件／部分。
2. 將主要元件與功能合理配對。
3. 將元件依主要功能分類到科技子系統。
4. 在教師說明後看懂四軸無人機的「輸入 → 處理 → 輸出 → 回授」簡化系統模型。

進階：能理解同一元件可能跨越多個功能，且不同科技產品不一定具有完全相同的子系統。

## 十、教師提問腳本

### 01～03 探究時
- 「你覺得它是在做什麼，而不是它叫什麼？」
- 「如果把這個拿掉，哪個功能會消失？」
- 「哪幾個零件其實是在完成同一種功能？」

### 04 統整時
- 「剛才分類是在看『有哪些功能』，現在這張圖是在看『這些功能怎麼一起運作』。」
- 「系統收到什麼？」
- 「誰負責判斷？」
- 「最後做出什麼動作？」
- 「做完之後，系統怎麼知道現在的實際狀態？」

### 銜接 M1
- 「下一關我們只把『結構』這一部分抽出來深入研究。」

## 十一、常見迷思

1. **無人機就是四顆馬達。**  
   馬達只負責動力的一部分，還需要能源、結構、控制等功能合作。

2. **控制器就是整個控制系統。**  
   控制是功能與過程，不只是某一顆硬體。

3. **感測器會直接控制馬達。**  
   感測器提供資料，控制邏輯再根據資料決定輸出。

4. **回授就是感測器本身。**  
   感測器是取得資料的元件；回授強調「把實際結果帶回控制端」的資訊流。

5. **所有科技系統都有固定七大子系統。**  
   七項分類是本課程分析工具，實際科技系統依任務需求而不同。
