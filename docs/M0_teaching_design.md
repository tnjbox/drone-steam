# M0｜系統解密：一架四軸無人機裡藏了什麼？

## 一、模組定位

M0 是「STEM創課-解密四軸無人機」的序章任務，目的不是先教完整飛行原理，也不是要求學生背零件名稱，而是建立一張能支撐 M1～M7 的科技系統地圖。

核心轉變：

> 從「看到一架無人機」→「看見多個子系統正在合作」

M0 完成後，學生應知道：一架四軸無人機不是四顆馬達加上一個機架，而是一個由結構、能源、動力、感測、控制、通訊與程式等功能共同組成的科技系統。

但要避免讓學生形成「所有科技產品都必須包含這七項」的錯誤概念。子系統分類是分析工具，實際系統可依任務而不同。

---

## 二、核心提問

**一架四軸無人機裡藏了什麼？**

延伸追問：

> 為什麼一架無人機不是只有四顆馬達？這些不同部分各自負責什麼，又怎麼合作？

---

## 三、核心概念鏈

> **任務需求 → 零件／元件 → 功能 → 子系統 → 子系統合作 → 完整科技系統**

M0 不要求學生一次背熟名詞，而是先從功能判斷，最後才形成子系統分類。

---

## 四、建議子系統分類

### 1. 結構 Structure
負責支撐、固定、保護與安排其他元件的位置。

在本課程可能看到：
- 積木機架
- 機臂
- 馬達固定結構
- 螺旋槳護罩

### 2. 能源 Energy
提供系統運作所需的電能。

在本課程可能看到：
- 3.7V 鋰電池
- 電源連接

### 3. 動力 Power / Actuation
把電能轉換成可以造成動作的輸出。

在本課程可能看到：
- 馬達
- 螺旋槳

### 4. 感測 Sensing
取得外界或自身狀態的資料。

本組無人機相關：
- ToF 距離感測
- Optical Flow 光流移動線索

### 5. 控制 Control
根據目標、感測資料或操作指令，決定輸出要如何改變。

可從「主控盒／控制板」切入，但不把控制簡化成某一顆零件；控制是一個功能。

### 6. 通訊 Communication
讓操作者、遙控器或其他裝置把命令傳給系統。

本組無人機可連結：
- 2.4G 遙控器
- micro:bit / 控制板之間的命令傳遞

### 7. 程式 Program / Algorithm
把任務規則、操作順序與判斷條件轉成機器可以執行的流程。

M0 只建立「程式也是系統的一部分」的概念，不提前進入 M6 的演算法細節。

---

## 五、教學設計原則

### 原則 1｜功能先於名詞

不要先投影七個分類讓學生抄。

先給實體零件或照片，問：

> 「它負責做什麼？」

再從功能逐步形成分類。

### 原則 2｜零件不等於子系統

同一個子系統可能包含多個元件；一個元件也可能同時參與多個功能。

例如主控盒不能只被理解成「控制系統的一顆零件」，其中可能同時涉及感測、控制與通訊。

### 原則 3｜系統重點是合作

學生最後不能只完成分類表，還需要回答：

> 「如果只有這些零件，但彼此沒有合作，還算是一架能完成任務的無人機嗎？」

### 原則 4｜M0 不深入後續原理

M0 只建立系統觀，不在此處詳細解釋：
- 重心與穩定 → M1
- 推力 → M2
- 四馬達協同 → M3
- ToF / Optical Flow 原理 → M4
- 回授控制 → M5
- 演算法 → M6

---

## 六、建議學習活動

M0 不需要大型模擬器，也不需要複雜量測。建議採「拆解、配對、分類、系統拼圖」活動。

### 01｜拆解挑戰：你猜裡面有什麼？

先展示完整四軸無人機或組裝模型，不先說答案。

學生先記錄：

> 「如果把它拆開，我猜會看到哪些東西？它們可能負責什麼？」

目的：揭露原有概念。

---

### 02｜零件與功能：它到底負責什麼？

讓學生觀察實體元件或教師準備的零件卡。

建議功能卡：
- 提供電力
- 產生推力
- 支撐與固定
- 保護螺旋槳
- 知道離地面多遠
- 看出相對移動線索
- 接收操作命令
- 決定下一步輸出
- 按照規則完成任務

學生先配對「元件 ↔ 功能」，再討論可能有不只一種答案的情況。

---

### 03｜子系統分類：哪些功能可以放在一起？

教師此時才引入：

> 結構｜能源｜動力｜感測｜控制｜通訊｜程式

讓學生把前一階段的功能重新分類。

關鍵不是分類全對，而是能說明理由。

---

### 04｜系統怎麼合作？

用一個最簡單的任務：

> 「我要讓無人機接收起飛命令並產生向上的動作。」

學生嘗試排列合作關係，例如：

> 操作者／程式 → 通訊／控制 → 動力 → 螺旋槳推動空氣 → 機體產生動作

若加入懸停概念，可只點到：

> 感測資料 → 控制 → 再調整輸出

不要深入 M5。

---

### 05｜我的科技系統地圖

學生完成一張簡化系統圖。

建議格式：

| 子系統 | 我看到的元件／例子 | 它的主要功能 |
|---|---|---|
| 結構 |  |  |
| 能源 |  |  |
| 動力 |  |  |
| 感測 |  |  |
| 控制 |  |  |
| 通訊 |  |  |
| 程式 |  |  |

最後再用一句話回答：

> **為什麼無人機是一個「系統」，而不是一堆零件？**

---

### 06｜下一個問題：如果「身體」改變呢？

以一個實體觀察收尾：

> 同樣的馬達與控制，如果機架變得不對稱、重心偏掉或重量分布不同，結果會不會一樣？

銜接 M1：

> **怎樣的「身體」比較穩？**

---

## 七、學生數位紀錄建議

M0 是序章，不需要大量書寫。

保留四類有價值的紀錄即可：

1. 起始預測：我猜有哪些零件／功能。
2. 功能與子系統分類結果。
3. 簡化科技系統地圖。
4. 一句解釋＋一個新問題。

不建議加入大量選擇題或背誦式名詞測驗。

---

## 八、完成標準

學生完成 M0 後，至少能：

1. 指出至少 4 個不同功能的元件或部分。
2. 將主要功能合理分類到至少 4 個子系統。
3. 說明至少一條「不同子系統如何合作完成任務」的關係。
4. 用自己的話解釋：為什麼無人機是一個科技系統。

進階：能指出同一元件可能跨越多個功能，或不同科技產品不一定具有完全相同的子系統。

---

## 九、教師提問腳本

### 不急著給答案
- 「你覺得它是在做什麼，而不是它叫什麼？」
- 「如果把這個拿掉，哪個功能會消失？」
- 「哪幾個零件其實是在完成同一種功能？」

### 引導系統觀
- 「這個部分自己能完成任務嗎？」
- 「它需要從哪裡得到資料或能量？」
- 「它的結果又要交給誰？」

### 銜接 M1
- 「如果所有電子元件都一樣，只改機架，會發生什麼事？」

---

## 十、常見迷思

1. **無人機就是四顆馬達。**  
   修正：馬達只負責動力的一部分，還需要能源、結構、控制等功能合作。

2. **控制器就是整個控制系統。**  
   修正：控制是功能與過程，不只是某一顆硬體。

3. **感測器會直接控制馬達。**  
   修正：感測器提供資料，控制邏輯再根據資料決定輸出。

4. **程式只是附加功能。**  
   修正：當任務需要自動化，程式就是把規則轉成可執行流程的重要部分。

5. **所有科技系統都有固定七大子系統。**  
   修正：七項分類是本課程分析工具，實際科技系統依任務需求而不同。

## 十二、是否需要模擬器？

M0 不建議建立大型模擬器。

M0 的核心是「實體觀察 → 功能判斷 → 分類 → 系統合作」，實體零件與分類活動比模擬更直接。

若未來需要數位輔助，最多做簡單拖曳式「元件／功能／子系統配對」，不應取代實體拆解。

---

## 十三、M0 → M1 銜接

M0 結論：

> 無人機是一個由多個子系統共同完成任務的科技系統。

下一個值得追問的問題：

> **如果「結構子系統」改變，無人機還會一樣穩嗎？**

進入 M1｜機體結構：

> **怎樣的「身體」比較穩？**
